1. 🚨 Critical Bugs & Memory Leaks
A. Multiple Lambda Connections Leak in ResponsePane / DriveApi
Location: ResponsePane::appendFileAttachment (src/ui/ResponsePane.cpp)
connect(drive, &DriveApi::attachmentDownloaded, this,
    [this, safePreview, fileId](const QString &id, const QByteArray &data, const QString &mimeType)
    { ... });
Issue: Every time a user selects a prompt pair containing an attachment, showResponse() calls appendFileAttachment(), creating a new signal-slot connection to drive->attachmentDownloaded. Because DriveApi is owned by MainWindow (persists for the app's lifetime), old lambda slots are never disconnected. Selecting prompts 50 times will result in 50 redundant lambda invocations for every single file download.
Fix: Store a connection handle or pass a context object and disconnect when clearing, or manage downloads through dedicated request tokens:
// Store connection and disconnect prior to creating a new one, or use QMetaObject::Connection
QMetaObject::Connection conn = connect(drive, &DriveApi::attachmentDownloaded, safePreview,
    [safePreview, fileId](const QString &id, const QByteArray &data, const QString &mimeType)
    {
        if (id == fileId && safePreview)
            safePreview->setContent(data, mimeType);
    });
B. Raw Pointer Leak in MainWindow (LocalCache)
Location: MainWindow.h / MainWindow.cpp
// MainWindow.h
LocalCache *m_cache;

// MainWindow.cpp constructor
m_cache(new LocalCache())
Issue: LocalCache does not inherit from QObject and is allocated with new, but is never deleted in MainWindow::~MainWindow(), causing a memory leak on application shutdown.
Fix: Either make m_cache a value member (LocalCache m_cache;) or manage it with std::unique_ptr<LocalCache>:
// MainWindow.h
std::unique_ptr<LocalCache> m_cache;
C. Invalid Selected Index After Sorting
Location: MainWindow.cpp (m_selectedConvIndex)
Issue: m_selectedConvIndex stores an integer row index. When the user changes the sort order via m_sortCombo, ConversationListPane::applySort() rearranges m_conversations. The integer m_selectedConvIndex in MainWindow now points to a completely different conversation.
Fix: Track conversations by fileId (QString m_selectedFileId) instead of an integer row index.
D. Drive Retry Logic Breaks Binary Attachment Downloads
Location: DriveApi.cpp (retryPendingRequests & downloadAttachment)
void DriveApi::retryPendingRequests()
{
    for (const auto &pending : retries)
        sendGet(pending.url, pending.callback); // Parses response as JSON!
}
Issue: sendGet assumes the response is a JSON document (QJsonDocument::fromJson). If an OAuth token expires while downloading a binary image/file (downloadAttachment), retryPendingRequests() calls sendGet(), which tries to parse PNG/PDF data as JSON and passes an empty QJsonObject to the callback, causing download failures.
Fix: Differentiate between JSON endpoints and binary media endpoints in PendingRequest.

2. 🔐 OAuth 2.0 & API Compliance
Out-Of-Band (OOB) Flow Deprecation
Location: AuthManager.cpp (urn:ietf:wg:oauth:2.0:oob)
m_redirectUri = "urn:ietf:wg:oauth:2.0:oob";
Issue: Google officially deprecated and disabled Out-Of-Band (OOB) flow (urn:ietf:wg:oauth:2.0:oob) for desktop applications to mitigate phishing risks. Newly created Google OAuth client IDs will reject this authorization flow with an invalid_request error.
Fix: Implement a local HTTP loopback server (e.g., listening on http://127.0.0.1:<random_port>/callback) using QTcpServer or QHttpServer to catch the OAuth authorization code automatically without manual copy-pasting.
Drive API Query Parameter Escaping
Location: DriveApi.cpp (findFolder and searchConversations)
query.addQueryItem("q", QString("name='%1' and ...").arg(folderName));
Issue: If folderName or a search query contains a single quote ' (e.g., User's Folder), the query string fails with HTTP 400 Bad Request.
Fix: Escape single quotes in Drive query strings (folderName.replace("'", "\\'")).

3. 🎨 UI / UX & Rendering Improvements
A. Embedding Attachments Inline in QTextBrowser
Location: ResponsePane.cpp
Current Behavior: Prompt text is displayed in QTextBrowser, but file attachments and inline images are appended as separate widgets to m_layout at the bottom of ResponsePane. If a prompt contains text followed by an image, the image is rendered below all text rather than in sequence.
Improvement: Load images directly into QTextDocument as resources:
// Clean inline embedding in QTextBrowser:
m_browser->document()->addResource(QTextDocument::ImageResource, QUrl("myimage://1"), pixmap);
m_browser->append("<img src='myimage://1'/>");
B. Robust Base64 Inline Image Handling
Location: ResponsePane.cpp (appendInlineImage)
Issue: Google AI Studio inline image data sometimes contains data URI prefixes (e.g., data:image/png;base64,iVBORw...). Passing this directly to QByteArray::fromBase64 will fail decoding.
Fix: Strip data URI headers prior to Base64 decoding:
QString base64 = base64data;
if (base64.contains(","))
    base64 = base64.section(',', 1);
QByteArray raw = QByteArray::fromBase64(base64.toUtf8());

4. ⚡ Database & Performance Optimizations
Named SQLite Connection
Location: LocalCache.cpp (LocalCache::init)
m_db = QSqlDatabase::addDatabase("QSQLITE");
Issue: Using addDatabase("QSQLITE") configures the default database connection. If LocalCache is re-created or accessed, Qt emits warnings (a connection named 'qt_sql_default_connection' already exists).
Fix: Specify a unique connection name:
m_db = QSqlDatabase::addDatabase("QSQLITE", "ViewerCacheConnection");
Timezone Robustness in Message Sorting
Location: ConversationModel.cpp
std::sort(conv.messages.begin(), conv.messages.end(),
    [](const Message &a, const Message &b)
    {
        if (a.createTime != b.createTime)
            return a.createTime < b.createTime;
        ...
    });
Issue: Direct QDateTime comparison can produce inaccurate results if one datetime instance contains a local offset and another is UTC (Qt::ISODateWithMs).
Fix: Compare epoch milliseconds:
return a.createTime.toMSecsSinceEpoch() < b.createTime.toMSecsSinceEpoch();
